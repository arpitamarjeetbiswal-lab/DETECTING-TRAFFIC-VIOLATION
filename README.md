
# Traffic Violation Detection

A React dashboard and Flask service for image-based motorcycle, helmet, and number-plate analysis. OCR output is an estimate and must be reviewed before use.

## Current capabilities

- Upload an image from the frontend and receive annotated detection results from Flask.
- Detect motorcycles, people, helmet status, and number plates.
- Estimate rider counts per motorcycle and flag possible triple riding for review.
- Associate plate detections with motorcycles when the overlap is clear.
- Count and save a no-helmet violation only when its detection is associated with a motorcycle; otherwise show it as an unmatched alert for review.
- Save possible triple-riding cases as review items in SQLite, with a matched plate when available.
- Display plate text, confidence, and review status in the upload results.
- Report analysis time in the results; EasyOCR uses CUDA when available and falls back to CPU if GPU initialization fails.
- Skip OCR for detected plates that do not clearly overlap a detected motorcycle.
- Store image-analysis history and confirmed or reviewable violation records in SQLite so they are available to every browser connected to the same backend. Older browser-local history is imported once on first connection.

Detection quality depends on image resolution, camera angle, lighting, and model training. Small or unclear plates may be reported as unreadable or incorrect; review all results.

This prototype accepts still images only. Video and live camera analysis are not implemented.

The SQLite database must live on persistent storage when deployed. If the hosting platform removes local files during restarts or redeploys, configure a persistent volume or migrate the database to a managed database service.

For a deployment where the frontend and backend use different origins, set `VITE_API_URL` to the public Flask API URL at frontend build time and set `CORS_ALLOWED_ORIGINS` to the frontend origin on Flask. The Flask development server can bind to the network with `FLASK_HOST=0.0.0.0`; use a production WSGI server for deployment.

## Deploy with Render

The repository includes a `render.yaml` Blueprint for a Singapore-region Flask API and a static frontend. Connect this repository to Render and create a Blueprint from the file. The API uses Gunicorn, CPU-only PyTorch, OpenCV headless, and a persistent disk mounted at `/var/data` for the SQLite database, uploads, and annotated results. The frontend build points at `https://trafficvision-api.onrender.com`; Flask allows the matching `https://trafficvision-web.onrender.com` origin. If Render assigns different service URLs, update `VITE_API_URL` on the static site and `CORS_ALLOWED_ORIGINS` on the API, then redeploy both.

The API is configured for Render's `1c-2g` (1 CPU, 2 GB RAM) plan. This is a paid service; check current hosting and disk pricing before creating the Blueprint. Render static sites are free, while the API's persistent disk requires a paid web service. Do not use the free API plan for the full model stack or persistent violation history.

## Requirements

- Python 3.10 or newer
- Node.js 20.19+ or 22.12+
- Git
- PyTorch and TorchVision. Install the build suited to your machine from the [official PyTorch installer](https://pytorch.org/get-started/locally/). For an NVIDIA GPU, select the installed CUDA option; CPU builds also work but are slower.

## Setup on Windows PowerShell

Run these commands from the repository root.

### 1. Install Python dependencies

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
```

Install PyTorch and TorchVision using the command generated by the [official PyTorch installer](https://pytorch.org/get-started/locally/). Select the matching CUDA build for NVIDIA GPU acceleration; the CPU build works too, but inference is slower. Then install the remaining Python dependencies:

```powershell
python -m pip install -r requirements.txt
```

If Python 3.12 is unavailable, use another installed Python version 3.10 or newer in the `py -3.12` command.

### 2. Start the Flask backend

Open a PowerShell window at the repository root:

```powershell
.\.venv\Scripts\Activate.ps1
python ai\scripts\flask_api.py
```

The API listens at `http://127.0.0.1:5000`. The first OCR run may download EasyOCR language data.

To force EasyOCR to use the CPU, set `$env:EASYOCR_GPU = "0"` in PowerShell before starting Flask.

### 3. Start the frontend

Open a second PowerShell window at the repository root:

```powershell
npm install
npm run dev
```

Open the local URL printed by Vite, normally `http://localhost:5173`.

## Model files

- `ai/models/best.pt` is the helmet model already tracked in Git.
- `yolov8n.pt` is used for person and motorcycle detection.
- `ai/runs/plate_detection/test_training_v2/weights/best.pt` is the trained plate detector used by the OCR service.

The last two model files are binary assets. Include them in the contribution only if their source and redistribution terms permit it. Do not add datasets, uploads, generated outputs, or the local SQLite database to a code commit.

## Git contribution scope

Review and contribute the code/documentation files deliberately. Keep `.venv*`, `node_modules`, datasets, uploads, generated run outputs, and `ai/traffic_violations.db` out of commits. Model weights should be reviewed for provenance and repository hosting limits before adding.
